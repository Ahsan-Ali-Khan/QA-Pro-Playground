# Locator Break Category Section Manual Steps to Reproduce
A — Locator Type Changes
1 Locator type change – tag Dynamic Elements
  1. Click Dynamic Elements in sidebar.
  2. Observe the Dynamic Attributes card — button has <button id="btn-click">.
  3. Wait 5–10 s (auto-mutation cycle) — the element tag may change to <div> or <span> with same text.
  4. A locator using //button[@id='btn-click'] or button#btn-click now fails.
2 Locator type change – id Dynamic Elements
  1. Click Dynamic Elements.
  2. In the Dynamic Attributes card, observe id="btn-click".
  3. Wait for auto-mutation or click Reset Playground and watch — the ID rotates (e.g., btn-click-1, btn-click-a3f).
  4. Any locator using #btn-click or By.id("btn-click") breaks.
3 Locator type change – class Dynamic Elements
  1. Click Dynamic Elements.
  2. Button starts with class="btn dyn-class".
  3. Wait 5–10 s — the class mutates (e.g., dyn-class-a4b2).
  4. A locator like .dyn-class or By.className("dyn-class") now returns no element.
4 Locator type change – dynamic attribute Dynamic Elements
  1. Click Dynamic Elements.
  2. Open browser DevTools → inspect #btn-click.
  3. Wait 8 s — data-reactid, data-v-XXXXXX, and __reactFiber$XXXXXXXX all change value.
  4. A locator using [@data-reactid='0.1.2'] or [data-v-abc123] breaks on next cycle.
5 Locator type change – name Forms
  1. Click Forms.
  2. In Stage 1, locate <input id="name">, <input id="phone"> etc.
  3. These inputs have no name attribute — a locator using By.name("name") fails immediately.
  4. Alternatively, navigate to Stage 2 Preferences subtab — select#language has no name attr.
6 Locator type change – regex/text contains Dynamic Text
  1. Click Dynamic Text.
  2. Select Partial Dynamic Text from the dropdown — the output box shows a sentence where only part of the text changes.
  3. A locator using contains(text(),'fixed-prefix') passes only when prefix matches; if prefix rotates, it breaks.
  4. Switch to Full Replacement mode — entire text changes every few seconds.
7 Locator type change – css Dynamic Elements
  1. Click Dynamic Elements.
  2. Note the CSS selector button.btn.dyn-class[data-testid="stableBtn"] at page load.
  3. Wait 8 s — class changes to a generated hash; the CSS selector no longer matches.
  4. Also click Dynamic Tables → ⚙ → uncheck a column: td:nth-child(3) selectors shift.
8 Locator type change – xpath Dynamic Elements
  1. Click Dynamic Elements.
  2. Record XPath: //div[@id='lab-attributes']/button.
  3. Click Reset Playground — the inner structure rebuilds; absolute XPath may shift by one node.
  4. Also try Dynamic Tables → Add Record, then delete a row: //table[@id='table2']/tbody/tr[2]/td[1] now points to a different record.
9 Locator type change – linkText (Selenium) Dynamic Text
  1. Click Dynamic Text.
  2. Select Full Replacement mode — anchor text in the output changes each cycle.
  3. A Selenium By.linkText("Visit our Docs") locator breaks when text rotates to a new phrase.
10 Locator type change – partialLinkText (Selenium) Dynamic Text
  1. Click Dynamic Text.
  2. Select Partial Dynamic Text — prefix is stable, suffix changes.
  3. A By.partialLinkText("Visit") locator passes initially.
  4. Switch to Special Characters mode — partial text now includes symbols that invalidate the match.
11 Locator type change – getByRole (Playwright) Web Components
  1. Click Custom Web Components.
  2. Inspect <qa-button> — its shadow DOM renders an inner button; the ARIA role may differ from a native <button>.
  3. getByRole('button', {name:'Click Me'}) fails if the shadow root doesn't expose the role to Playwright's accessibility tree.
12 Locator type change – getByText (Playwright) Dynamic Text
  1. Click Dynamic Text.
  2. Select Full Replacement — text in #dynamicOutput replaces every few seconds.
  3. getByText('Loading dashboard...') only matches during one cycle; next cycle the text is different.
13 Locator type change – getByLabel (Playwright) Forms
  1. Click Forms → Stage 1.
  2. Labels like Full Name, Phone, Date of Birth are present.
  3. Click Next to Stage 2 → click Preferences subtab — the label text changes context.
  4. getByLabel('Full Name') on Stage 2 finds nothing; if the label changes locale (Environment section), it also breaks.
14 Locator type change – getByPlaceholder (Playwright) Autocomplete
  1. Click Autocomplete.
  2. Observe <input placeholder="Type a country name...">.
  3. Click Environment → change locale to a non-English option — the placeholder text may shift.
  4. getByPlaceholder('Type a country name...') no longer matches after locale change.
15 Locator type change – getByAltText (Playwright) Lazy Load
  1. Click Lazy Load Images.
  2. Scroll down inside the grid — images load with alt="Mountain Vista" etc.
  3. Trigger a section reset (navigate away and back) — alt text is regenerated from the PICS array; if order changes, getByAltText('Mountain Vista') targets the wrong card.
16 Locator type change – getByTitle (Playwright) Frameset
  1. Click Frameset / Multi-Frame.
  2. The embedded <iframe title="Frameset Playground"> is found by getByTitle('Frameset Playground').
  3. Click Spawn New Frame in the iFrame section — a new frame is created without a title; the original title locator now matches the wrong frame.
17 Locator type change – getByTestId (Playwright) Dynamic Elements
  1. Click Dynamic Elements.
  2. Button starts with data-testid="stableBtn".
  3. Wait 8 s for auto-mutation — the data-testid rotates to a generated value like stableBtn-4f2a.
  4. getByTestId('stableBtn') returns no match.
18 Locator type change – frameLocator iFrame
  1. Click iFrame.
  2. The active frame is id="frame0". Note the Frame ID shown in the status box.
  3. Click Spawn New Frame — a second iframe is added with a new incremental ID (frame1).
  4. Click Reload Frame — the reload counter increments; if frame ID is rebuilt, frameLocator('#frame0') may point to a stale handle.
19 Locator type change – shadow DOM Shadow DOM
  1. Click Shadow DOM.
  2. Select mode Open — a shadow root is attached to #shadow-host.
  3. Switch to Nested mode — a shadow inside a shadow is created.
  4. Locators using standard driver.findElement(By.css('qa-input input')) fail without shadow-piercing syntax.
20 Locator type change – nth/first/last Dynamic Tables
  1. Click Dynamic Tables.
  2. Note the first row's data.
  3. Click + Add Record, fill the modal, click Save — new row appears at top or bottom.
  4. tr:first-child, tr:last-child, or tr:nth-child(2) now points to a different record.
21 Locator type change – relative locator Dynamic Elements
  1. Click Dynamic Elements.
  2. Locate the Catch Me If You Can card — the button randomly repositions.
  3. A relative locator like "button near label X" breaks when the button moves to a different card.
22 Locator type change – parent-child Accordion
  1. Click Accordion.
  2. All but the first .acc-body are DOM-removed (not hidden — physically absent).
  3. A locator like .acc-item > .acc-body returns NoSuchElementException for collapsed items.
  4. Click a header to expand — the body is re-inserted; click another header — the first body is removed again.
23 Locator type change – ancestor-descendant Tree Menu
  1. Click Tree Menu.
  2. All sub-lists (ul) are DOM-removed on init; only toggles are visible.
  3. An XPath like //li[.//span='Selenium']//ul/li returns nothing (ul is detached).
  4. Click the toggle next to Selenium to expand it — the ul re-enters DOM and descendant locators work again.
24 Locator type change – sibling locator Dynamic Tables
  1. Click Dynamic Tables.
  2. Click ⚙ (gear icon) → uncheck a column (e.g., Date).
  3. The column is removed from DOM — following-sibling::td[2] now refers to a different column.
  4. Re-check the column — column re-inserts but may be at a different position in the sibling chain.
25 Locator type change – multi-attribute Dynamic Elements
  1. Click Dynamic Elements.
  2. Button starts with id="btn-click" class="btn dyn-class" data-testid="stableBtn".
  3. Wait 8 s — all three attributes mutate simultaneously.
  4. An XPath like //button[@id='btn-click' and @class='btn dyn-class' and @data-testid='stableBtn'] fails.
26 Locator type change – indexed locator Infinite Scroll
  1. Click Infinite Scroll.
  2. Scroll to the bottom of the table — a new batch of 15 rows appends.
  3. A locator using tr[data-row-id='5'] or row index 5 in the tbody now points to a different logical position after more rows load.

  2. Inspect #btn-click — class is btn dyn-class.

30 Wrong Syntax Any Section
  1. Attempt to locate any element using an invalid XPath such as //button[id='btn-click'] (missing @ before id).
  2. Or use CSS selector button..dyn-class (double dot).
  3. Driver raises InvalidSelectorException immediately regardless of element presence.
  4. Use Dynamic Elements as a controlled target to test your selector syntax.

C — DOM Structure & Hierarchy
39 Deep DOM hierarchy Shadow DOM
  1. Click Shadow DOM → select Nested mode.
  2. A shadow host contains a shadow root, which contains another custom element with its own shadow root.
  3. Standard driver.findElement(By.css('input')) finds nothing — requires JS executor to pierce each shadow boundary.
40 Sibling dependency Dynamic Tables
  1. Click Dynamic Tables.
  2. Click ⚙ → uncheck the Status column — the TD disappears from DOM.
  3. A locator like td + td + td (adjacent sibling chain) now maps to the wrong cell.
  4. Re-check Status — the column re-inserts; sibling positions shift again.
41 Element index changes Dynamic Tables
  1. Click Dynamic Tables.
  2. Note row order. Click a column header to sort — rows reorder.
  3. Use Global Search to filter — visible row indices change.
  4. tr:nth-child(3) or tbody/tr[3] now points to a different record.
42 Nested elements iFrame
  1. Click iFrame.
  2. The page contains iframe#frame0 which loads frames/level1.html, which embeds frames/level2.html.
  3. To access a button in Level 2, automation must switch context twice: driver.switchTo().frame("frame0") then driver.switchTo().frame(level2_iframe).
43 Parent-child dependency Accordion
  1. Click Accordion.
  2. The .acc-body of a collapsed item is physically removed from DOM (not hidden).
  3. driver.findElement(By.css('.acc-item:nth-child(2) .acc-body')) throws NoSuchElementException.
  4. Click the item's header to expand — body re-enters DOM and becomes locatable.
44 Iframe iFrame
  1. Click iFrame.
  2. Elements inside #frame0 (e.g., the login form in Level 1) cannot be reached without driver.switchTo().frame("frame0").
  3. Without frame switch, any locator for inner elements returns NoSuchElementException.
45 Nested iframe iFrame
  1. Click iFrame.
  2. Level 1 frame embeds a Level 2 iframe, which embeds a Level 3 iframe.
  3. To reach Level 3 elements, switch frame context three times; missing one switch yields NoSuchElementException in the wrong frame.
46 Shadow DOM Shadow DOM
  1. Click Shadow DOM → select Open mode.
  2. The #shadow-host element gets a shadow root containing inputs and buttons.
  3. driver.findElement(By.css('#shadow-host input')) fails — must use JS executor: driver.executeScript("return arguments[0].shadowRoot.querySelector('input')", host).
47 Nested shadow DOM Shadow DOM
  1. Click Shadow DOM → select Nested mode.
  2. Inner custom element has its own shadow root inside the outer shadow root.
  3. Must pierce two shadow boundaries via chained JS executor calls; any single-level pierce fails to find the deepest elements.
48 Duplicate locators Dynamic Elements
  1. Click Dynamic Elements → find the Duplicate Locator Trap card.
  2. The #duplicate-box contains multiple <button class="dup"> elements.
  3. A CSS locator .dup returns a list; clicking index [0] may be wrong if the list order changes.

  1. Click Dynamic Elements → Duplicate Locator Trap card.
  2. All <button class="dup">Duplicate</button> buttons have identical class, text, and no unique ID.

  1. Click Dynamic Elements → Duplicate Locator Trap.
  2. Multiple buttons read "Duplicate" — getByText('Duplicate') or By.xpath("//button[text()='Duplicate']") matches all of them.

51 Elements with same attributes Dynamic Elements
  1. Click Dynamic Elements → Duplicate Locator Trap.
  2. All .dup buttons share identical class attribute with no other distinguishing attribute.
  3. [class='dup'] returns multiple nodes; attempting to click raises ambiguity or clicks the wrong button.
D — Visibility, State & Timing
52 Element disappears and reappears Slow & Disappearing
  1. Click Slow & Disappearing Elements.
  2. Click Trigger Process — the #statusBox appears, then disappears after a few seconds.
  3. A locator timed to catch the element while it is visible fails if it fires before the element appears or after it disappears.
53 Stale element reference Dynamic Elements
  1. Click Dynamic Elements → DOM Re-Render card.
  2. Cache a reference to the #rerender-btn button in your script.
  3. The button is periodically removed from DOM and re-inserted (rerender) — the cached reference is now stale.
  4. Attempting to interact with the stale reference raises StaleElementReferenceException.
54 Delayed rendering Dynamic Elements
  1. Click Dynamic Elements → Delayed Rendering card.
  2. The #delayed-btn has class="hidden" on page load — it appears after a 3–5 s delay.
  3. An automation script that immediately checks for the button before the delay expires gets ElementNotVisibleException or NoSuchElementException.
55 Lazy loaded elements Lazy Load
  1. Click Lazy Load Images.
  2. The 12 image cards are rendered but their <img> tags have data-ll-src (not src) — images only start loading when scrolled into view.
  3. A locator targeting img[src] finds nothing until the card enters the viewport.
  4. Scroll down inside the grid — after 4–5 s the src is set and the image appears.
56 Infinite scrolling elements Infinite Scroll
  1. Click Infinite Scroll.
  2. Table loads first 15 rows. Scroll to the bottom — another 15 rows append after ~700 ms.
  3. A locator for tr[data-row-id='20'] returns nothing until that batch loads.
  4. After second scroll, row 20 exists; before that point it does not.
57 Hidden elements Invisible but Present
  1. Click Invisible but Present.
  2. Three elements are present in DOM but invisible: one has opacity:0, one has visibility:hidden, one has color:transparent.
  3. Selenium finds them via findElement but attempting to click raises ElementNotInteractableException.
  4. Click Make Visible — they become interactable.
58 Disabled elements Dynamic Elements
  1. Click Dynamic Elements → Async Enable Button card.
  2. #async-btn is disabled on page load.
  3. Attempting to click it immediately raises ElementNotInteractableException.
  4. Wait ~3 s for the async enable — the disabled attribute is removed and the button becomes clickable.
59 Readonly elements Forms
  1. Click Forms → proceed to Stage 4 (Review) by clicking Next three times.
  2. The review data in #reviewData is read-only text — no input fields to interact with.
  3. If your automation tries to type into the review summary, it finds no editable input (ElementNotInteractableException).
60 Collapsed elements Accordion
  1. Click Accordion.
  2. Items 2–4 start collapsed — their .acc-body is physically removed from DOM.
  3. A locator for .acc-item:nth-child(3) .acc-body raises NoSuchElementException.

61 Expanded elements Tree Menu
  1. Click Tree Menu.

  3. A locator for .tree-leaf inside the expanded li now finds 3 results.

62 Overlapping elements Ad / Banner Overlay
  1. Click Ad / Banner Overlay.
  2. Two target buttons (#ad-submit-btn, #ad-checkout-btn) are visible.
  3. Click Show Ad — the #adBanner overlay appears covering both buttons.

63 Offscreen elements Offscreen Elements
  1. Click Offscreen Elements.
  2. Inside the scrollable #offscreen-container, a target element is positioned far below the visible area.
  3. Automation that checks visibility returns false; clicking without scrolling raises MoveTargetOutOfBoundsException.
  4. Click Scroll to Target to bring it into view.
64 Invisible but present elements Invisible but Present
  1. Click Invisible but Present.
  2. The button with opacity:0 is in DOM and technically "present" — driver.findElement succeeds.
  3. But isDisplayed() returns false / element.isVisible() is false in Playwright.
  4. Test suites checking visibility before acting will skip the element even though it exists.

  2. The target element is positioned well below the visible scroll area inside #offscreen-container.
  3. Without scrolling the container, the element is outside the intersection observer's viewport; isInViewport returns false.
  4. Scroll the container or use scrollIntoView() before interacting.
69 Sticky/floating elements Offscreen Elements
  1. Click Offscreen Elements.
  2. The section header or a sticky button overlaps the target element at certain scroll positions.
  3. Automation that clicks coordinates for the target may hit the sticky overlay instead, getting ElementClickInterceptedException.
70 Slow network conditions Slow & Disappearing
  1. Click Slow & Disappearing Elements.

  2. Click Trigger Process — the #spinnerStatus text cycles through stages ("Triggered…" → "Loading…" → "Processing…" → "Done").

72 Race condition timing issues Dynamic Elements
  1. Click Dynamic Elements → Flaky Visibility card.
  2. #toggle-btn alternates between visible and hidden on a random interval.
  3. Automation may pass or fail depending on which phase it catches — classic race condition.
  4. Also reproducible in Delayed Rendering: script and element reach ready state at unpredictable order.
73 Captcha/Bot-detection scripts CAPTCHA Lab

  2. A 3×3 image grid is generated — you must select all tiles matching the displayed target category.
  3. After each verify attempt the grid regenerates with new random tiles and a new target.
  4. Automation cannot use static locators for tile content; must read data-cat attributes dynamically.
74 DOM refresh after action Dynamic Tables
  1. Click Dynamic Tables.
  2. Click + Add Record → fill form → Save — a new row is inserted into #table2 tbody.

  3. Any element references captured inside the frame before reload are now stale.
  4. The Reload Counter increments — the frame ID also changes; frame-context locators that use the old ID break.

85 Toast messages — Dynamic ID Toast Messages
  1. Click Toast Messages in the sidebar.
  2. Click any type button (e.g., ✅ Success Toast).

  1. Click Toast Messages.
  2. Click ✅ Success Toast — toast appears top-right.
  3. Wait 3 s — toast slides out and is removed from DOM (not hidden).
  4. Any locator asserted after 3 s returns NoSuchElementException.
  5. Automation must assert within the 3 s window; use an explicit wait for the element to appear, then immediately read its text before it disappears.
85c Toast messages — Stacked / Multiple simultaneous Toast Messages
  1. Click Toast Messages.
  2. Click ⚡ Rapid Fire (3 toasts) — three toasts appear 300 ms apart (Success, Info, Warning), all stacked vertically in #toast-container.
  3. A locator .qa-toast now matches 3 elements — automation clicking the first may interact with the wrong toast.
